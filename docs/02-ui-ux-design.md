# 02 — UI/UX 및 디자인 시스템

## 1. 시각적 기준
사용자가 첨부한 `think thing thank` 웹사이트 이미지를 디자인 레퍼런스로 사용한다. 특정 사이트를 픽셀 단위로 복제하지 않고 다음 시각적 특성을 적용한다.
- 흰색 또는 아주 옅은 배경
- 검정 텍스트와 흑백 중심의 제한된 팔레트
- 화면 폭을 활용하는 큰 헤드라인
- 산세리프와 이탤릭 세리프의 대비
- 충분한 여백과 단순한 상단 내비게이션
- 중앙에 배치된 기하학적 원형 요소
- 하단에 작고 정돈된 보조 정보

## 2. 디자인 토큰
```css
:root {
  --color-bg: #ffffff;
  --color-text: #080808;
  --color-muted: #777777;
  --color-line: #e8e8e8;
  --color-soft: #f5f5f3;
  --color-positive: #246b45;
  --color-negative: #a33b35;
  --color-neutral: #555555;

  --font-sans: Arial, Helvetica, sans-serif;
  --font-serif: Georgia, "Times New Roman", serif;

  --space-1: 0.5rem;
  --space-2: 1rem;
  --space-3: 1.5rem;
  --space-4: 2rem;
  --space-5: 3rem;
  --space-6: 5rem;

  --content-width: 1120px;
  --radius-small: 4px;
}
```
외부 폰트를 추가해야 한다면 라이선스와 로딩 실패 대체 글꼴을 확인한다. 우선 시스템 폰트로 구현한다.

## 3. 화면 구성
### Header
- 좌측에 텍스트 기반 워드마크
- 우측에는 `About`, `How it works` 등 1~2개의 보조 링크만 배치 가능
- 실제 페이지가 없는 링크나 가짜 메뉴는 만들지 않는다. 링크가 필요 없으면 텍스트 링크를 생략한다.
- 높이는 작게, 좌우 패딩은 넉넉하게 유지한다.

### Hero
- 서비스의 목적을 한 문장으로 설명한다.
- 핵심 단어 일부는 이탤릭 세리프 스타일로 대비를 준다.
- 데스크톱에서 큰 글자를 사용하되 가로 넘침이 발생하지 않도록 `clamp()` 사용.
- 헤드라인 문구는 예시 문구를 임시로 사용하고, 서비스가 진단/상담을 제공한다고 오해하게 만들지 않는다.

### 중앙 그래픽
- 레퍼런스의 세 개 원을 추상적 시각 요소로 활용할 수 있다.
- 원은 긍정/부정/중립의 세 가지 감성 카테고리를 상징할 수 있지만, 색상만으로 결과를 전달하지 않는다.
- 모바일에서는 원의 크기와 간격을 줄이거나 세로 배치한다.
- 그래픽은 입력 폼보다 시각적 우선순위가 높아서는 안 된다.

### Analysis Form
- 명확한 라벨이 있는 다중 행 textarea
- placeholder는 입력 예시만 제공하고 라벨을 대체하지 않는다.
- 글자 수 `현재 글자 수 / 5,000` 표시
- 분석 버튼은 명확한 동사형 레이블 사용: `감정 분석하기`
- 빈 입력 또는 글자 수 초과 시 버튼/입력 주변에 안내
- 개인정보 및 민감정보 입력 주의 문구 표시

### Result
- 결과가 없을 때는 결과 영역을 숨기거나 차분한 빈 상태로 둔다.
- 성공 시 라벨을 가장 먼저 보여준다.
- 신뢰도는 숫자와 진행 막대 또는 텍스트로 함께 표현 가능하다.
- 분석 이유는 짧은 문단으로 표시한다.
- 색상, 아이콘, 텍스트를 함께 사용해 색각 차이가 있어도 의미를 파악할 수 있게 한다.
- 이전 결과를 새 분석 결과로 오인하지 않도록 새 요청 시작 시 이전 결과를 숨기거나 명확히 구분한다.

### Footer
- 작고 절제된 서비스 설명/저작권 표시
- 실제 주소, 이메일, 전화번호를 임의로 만들지 않는다.
- 개인정보 안내 링크가 아직 없다면 존재하지 않는 링크를 표시하지 않는다.

## 4. 상태별 UI
- 기본: 입력 가능, 결과 없음
- 입력 오류: 필드 가까이에 설명
- 로딩: 버튼 비활성화, 진행 중 텍스트 표시, 중복 제출 차단
- 성공: 결과 카드/영역 표시
- 실패: 오류 안내와 재시도 동작 제공
- 저장 실패: 분석 자체의 성공 여부와 저장 여부를 혼동하지 않게 별도 안내

## 5. 반응형 기준
- 최소 지원 폭: 360px
- 태블릿: 768px 전후
- 데스크톱: 1024px 이상
- 본문 최대 폭은 약 1120px, 입력 폼은 읽기 쉬운 폭으로 제한한다.
- 모바일에서 헤드라인, 원형 그래픽, 버튼이 화면 밖으로 넘치지 않아야 한다.
- 터치 대상은 충분한 크기를 확보한다.

## 6. 모션
- hover/focus 전환은 짧고 절제되게 적용한다.
- 로딩 상태는 과도하게 움직이지 않는다.
- `prefers-reduced-motion: reduce`를 존중한다.
- 분석 결과가 나타날 때 짧은 opacity 전환 정도만 허용한다.

## 7. 접근성
- 모든 입력 요소에 연결된 `label` 제공
- 버튼은 실제 `button` 요소 사용
- 결과/오류 영역에 적절한 `aria-live` 사용
- 키보드 포커스가 명확히 보이도록 한다.
- 텍스트 대비를 확보하고 색상만으로 상태를 표현하지 않는다.
- 장식용 그래픽은 보조기술에서 숨길 수 있다.

## 8. UI 검증 기준
- [ ] 첨부 이미지의 미니멀 흑백 분위기와 충분한 여백이 반영됐다.
- [ ] 텍스트 입력과 분석 버튼이 첫 화면에서 쉽게 발견된다.
- [ ] 360px 폭에서 가로 스크롤이 생기지 않는다.
- [ ] 긍정/부정/중립이 텍스트로 구분된다.
- [ ] 로딩/성공/오류 상태가 각각 명확하다.
- [ ] 키보드만으로 입력 및 분석이 가능하다.
