# 06 — 테스트, 배포 및 인수 기준

## 1. 테스트 환경
- 로컬 개발 환경
- Supabase 개발 프로젝트
- OpenAI API 키 및 사용 가능한 모델
- Vercel Preview 배포
- 최종 Vercel Production 배포

실제 키가 없는 환경에서는 API 호출을 모의(mock)해 UI와 오류 흐름을 확인할 수 있다. 모의 결과를 실제 AI 분석이 완료된 것처럼 보고하지 않는다.

## 3. 보안 테스트
- 브라우저 개발자 도구에서 OpenAI API 키가 보이지 않는지 확인
- 정적 파일과 JS 번들에 Supabase service role 키가 없는지 확인
- `.env` 파일이 Git에 포함되지 않는지 확인
- 서버 입력 검증 우회가 불가능한지 확인
- XSS 문자열이 화면에서 실행되지 않는지 확인
- RLS 활성화 여부 확인
- 사용자 화면에 내부 스택 트레이스가 표시되지 않는지 확인

## 4. 반응형/접근성 테스트
- 360px 모바일, 768px 태블릿, 1440px 데스크톱에서 확인
- 키보드 Tab/Shift+Tab으로 모든 컨트롤 접근
- Enter/Space로 버튼 활성화
- textarea 라벨과 오류 안내가 보조기술에 전달되는지 확인
- 결과 라벨을 색상 없이도 구분할 수 있는지 확인
- 모션 감소 설정에서 불필요한 애니메이션이 줄어드는지 확인

## 5. Supabase 설정 절차
1. Supabase 프로젝트 생성
2. SQL Editor에서 `docs/05-database-supabase.md`의 스키마 SQL 실행
3. Project URL과 service role 키를 안전하게 확인
4. 해당 값을 로컬 환경 변수에 등록
5. 실제 키가 코드 저장소에 들어가지 않았는지 확인

## 6. OpenAI 설정 절차
1. OpenAI API 계정 및 API 키 준비
2. 프로젝트에서 사용할 수 있는 모델을 선택
3. `OPENAI_API_KEY`, `OPENAI_MODEL` 환경 변수 설정
4. 사용량/비용 제한 및 모니터링 정책 확인
5. 모델 이름이나 API 형식이 변경되면 백엔드 구현과 테스트를 함께 갱신

모델명은 에이전트가 임의로 고정하지 않는다.

## 7. Vercel 배포 절차
1. 프로젝트를 Git 저장소에 커밋한다. 비밀 파일은 제외한다.
2. Vercel에서 저장소를 연결한다.
3. 정적 사이트와 `api/` Function이 올바르게 인식되는지 확인한다.
4. Vercel Project Settings → Environment Variables에 아래 값을 등록한다.
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
5. Preview 환경에서 전체 테스트를 수행한다.
6. 통과하면 Production 배포한다.
7. 배포 URL에서 모바일/데스크톱 및 실제 AI/DB 연동을 확인한다.

## 8. 최종 인수 체크리스트
### 기능
- [ ] 입력 → 분석 요청 → 결과 표시가 동작한다.
- [ ] 긍정/부정/중립 세 결과가 허용된다.
- [ ] 신뢰도 백분율과 분석 이유가 표시된다.
- [ ] 오류 상황별 메시지가 표시된다.
- [ ] 성공 데이터가 Supabase에 저장된다.

### 디자인
- [ ] 첨부 레퍼런스의 흑백 미니멀 디자인 방향이 반영됐다.
- [ ] 충분한 여백과 타이포그래피 위계가 있다.
- [ ] 모바일과 데스크톱에서 레이아웃이 정상이다.

### 보안/운영
- [ ] 비밀 키가 클라이언트에 노출되지 않는다.
- [ ] 입력 및 AI 응답 검증이 서버에 있다.
- [ ] DB RLS가 활성화돼 있다.
- [ ] 실제 서비스의 개인정보 안내/보관 정책이 결정됐다.
- [ ] Vercel Production URL에서 테스트가 통과했다.
